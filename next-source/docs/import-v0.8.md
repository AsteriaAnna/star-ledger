# 星账 0.8 导入修正核验预览

本版对应2026-09-29确认的修正计划。发布状态为核验预览：合成样本与浏览器验证已完成，用户提到的两份真实169条账单尚未提供，不能声称完成真实账单验收。Android/iPhone没有实机验收。

## 本次实现

- 账户按平台、账单归属、渠道和付款/到账角色保存已确认关系，随账务操作加密同步；名称或尾号只建议，首次必须确认。账户改名保留关系；同尾号、空渠道、组合支付不自动绑定。
- 按渠道/事件/状态分组。批量操作只作用于当前范围内勾选的记录，默认填补未知账户；替换已有账户需另用按钮，并先看变更预览。空渠道不保存通用映射。
- 导入待办持久保存、可暂缓、忽略及恢复；忽略决定同步，本机未提交队列纳入JSON备份但不跨设备同步。
- 明确花呗还款不作为消费；失败记录保留但无账务影响。独立退款与原消费退款状态分开。亲情卡受益人关系可按组确认；“不计收支”本身不阻断已确认代付消费。
- 来源身份独立于可编辑的交易类型。重导检查新版来源关联及旧版证据中的订单号，不因识别升级直接新增交易。缺少可靠身份时提示相似记录，由用户明确确认独立或关联。
- 两端并发导入同一来源会形成来源/账务冲突并停止不确定统计，不静默重复计算。
- 日期按组成校验并补零；中国官方账单统一北京时间解释；只有日期的条目需补时间。金额支持人民币单位及规范千分位，负号语义未知时保留核验。
- OCR完整标签提取，避免“商品说明”被截成“说明”。保留行边界与原始文本。
- 收支列和渠道列分开，按候选列优先级读取。未知模板不默认当支付宝。
- 可关闭预算；余额未知、未来期初、关闭跟踪、冲突等使用不同说明。还款/转账/提现按角色限制账户候选。
- 旧版来源提供只读核验清单；不修改已入账账户、类型、时间或金额。

## 使用顺序

1. 建立资产/负债账户，期初余额不确定可留空。
2. 导入文件，确认账单归属（例如“本人”或“另一个微信号”）；相同归属以后保持一致。
3. 选择渠道分组并勾选。选账户后“预览填补选中未知账户”，确认影响条数；可记住明确渠道关系。
4. 亲情卡消费可分组确认本人受益；未知交易性质可分组选择。退款关联、组合资金分摊等不会因选了账户而自动通过。
5. 选中无阻塞记录入账。其他条目稍后处理或忽略；关闭页面后仍保留。
6. 设置里查看/停止账户关系记忆。停止记忆不修改历史账单。

## 存储、同步及迁移

浏览器仍使用原数据库名称，IndexedDB版本由1升到2；保留所有旧操作、设备ID、同步状态，增加imports/importRevision。打开旧版本的页面会阻止升级，应关闭其他星账页面再重新打开。新页面收到版本变化会关闭旧连接。不得用旧版本程序写入升级后的数据库。

SQLite schema 3→4仅增加import_rules表；既有交易和来源不改。import_rules使用现有因果操作日志记录账户关系、忽略决定和来源关联，字段值整体合并，避免账户关系被拆成混合版本。同一键并发相同值合并，不同值显式冲突。新实体不用于存储真实交易金额分录。

网页同步仍先完整下载、解密和验证远端历史，再上传本机操作；未知实体/字段拒绝整批，不能先写部分数据。0.7网页客户端会拒绝新增规则数据，应所有网页设备升级后继续同步。旧版Node命令行客户端上传优先，不能保证它在上传前发现新版实体，因此本预览不支持混用旧版CLI；新SQLite程序必须使用本版源码。旧客户端无法被新版远程修改。

备份格式升至2并包含本机导入队列；仍可恢复格式1。队列保存使用修订号比较，过期窗口不能覆盖另一窗口。入账操作、来源关联及队列提交标记在同一IndexedDB写入中保存，失败不产生半笔提交。

来源证据内容保持不可变。新版交易采用独立交易/证据ID，以稳定来源关联和重复来源会计校验捕获跨设备并发，不能依赖同一随机操作ID。旧证据保留旧ID；读取时建立候选关联，不改旧操作日志。
