# 星账 · 网页个人版 0.7.1

本次交付形态：GitHub Pages 静态网页，同一个链接提供手机与电脑页面。

## 双端页面

- 电脑：固定侧栏、概览、账单表格、账户卡片、分析、导入核验、设置。支持筛选、批量分类、批量移除、连续查看上一笔/下一笔、CSV 导出。
- 手机：底部导航、单列账单、快捷记账按钮、截图输入、账户与消费查看。导入入口在概览及「更多」中。
- 页面根据宽度自动适配；设置中可切换电脑/手机模式。
- 星空暗色与克制的绿色视觉；初次打开为空账本，演示数据必须主动开启，演示账本禁止上传同步。

## 使用顺序

1. 添加账户，填写期初时刻的余额；不确定时留空。
2. 手动记录或选择支付详情截图。截图在浏览器本地 OCR，核对后保存。
3. 官方账单支持 XLSX/CSV，预览后批量匹配账户。退款必须关联原消费，对外转账的消费用途由用户确认。
4. 相同来源重复导入会跳过；相同金额、类型、日期附近的记录提供人工核验与凭证关联入口。
5. 可在设置中使用私有 GitHub 数据仓库进行加密同步。两端使用相同仓库、分支、账本 ID 和 43 位恢复密钥。
6. 定期导出 JSON 备份。备份为明文，需自行妥善保管。恢复会合并已有账务记录。

## 数据和账户边界

网页使用 IndexedDB 持久保存操作历史与同步状态，重新打开后保留。复用现有 Transaction / SourceRecord / BalanceMovement / ConsumptionEffect 账务核心。

网站只发布代码，不发布真实账单、令牌或恢复密钥。数据同步使用独立私有仓库。访问令牌和密钥仅保留在页面会话内，重新打开需再次提供。

预算、分类选项列表与显示偏好为本机设置。账单分类值和备注随账务记录同步。备注可使用 #标签 并搜索。

原始来源文本与订单标识不可被业务编辑覆盖。截图 OCR 保留识别文本及图片指纹；本版未将原截图图片纳入长期存储或同步，原图片请自行保留。

## 明确限制

- 网页通过选择图片输入，不声称实现 Android 系统分享接收或后台自动截图监控。
- OCR 首次需联网下载引擎与模型。识别结果必须人工核对；不承诺所有支付截图版式都准确。
- 现有账单可修改名称、分类、备注和未知账户补认。已完成的普通消费、收入可在详情中「更正金额」，填写原因后原子更新余额与消费，并追加不可修改的更正凭证。有关联退款（含待完成退款）或同步冲突时禁止直接更正。
- 其他类型的金额、既有账户与类型录错时，仍通过移除旧记录后重新记账纠正。已有关联退款时先处理退款。
- 简单名称、分类、备注冲突可在设置中明确解决；复杂整笔账务冲突保留双方记录并暂停合计，本版不提供全部复杂冲突的 UI。
- 源码使用全操作历史投影，面向个人初期数据量，尚未作多年大数据量性能验收。
- 浏览器清除网站数据会删除本机账本；离线缓存不是数据备份。
- 旧版网页与新版使用不同数据存储，未自动迁移旧版数据。

## 开发

Node.js 24 或以上：

```sh
npm ci
npm run dev:web
npm run build:web
npm test
npx tsc -p apps/web/tsconfig.json --noEmit
```

发布 `web-dist/` 的内容到网站的 `next/` 目录。完整源码在 `next-source/`，不需要任何服务端进程。

OCR 使用 Tesseract.js 6.0.1（Apache-2.0），OCR core URL 固定到 6.1.2。Excel 读取使用 read-excel-file 5.8.8（MIT），SHA-256 使用 @noble/hashes 1.8.0（MIT）。依赖版本与许可见 package-lock.json 及各包声明。
