# 单人版导入 0.9

## 目标与交互

首次导入不要求先建账户。识别后按资金渠道集中列出账户：可以接受预填名称创建、绑定已有账户并改名，或稍后设置。同一物理银行卡跨微信、支付宝复用；账户显示名改变不影响已记忆关系。新账户余额未知，之后补充余额基准。

| 位置 | 改动 | 目的 |
|---|---|---|
| apps/web/src/channels.ts、account-matcher.ts | 拆出优惠抵扣；按平台钱包或银行、卡类型、尾号识别；独立保存渠道与账户 ID 关系 | 名称可改、关系稳定；唯一匹配自动使用 |
| apps/web/src/import-accounts.ts、main.ts | 集中创建 / 绑定 / 改名，按渠道一次设置；直接导入当前范围可入账记录 | 减少逐笔核对和页面往返 |
| apps/web/src/importer.ts、categories.ts | 亲情卡消费免确认；支付宝分类映射、微信关键词分类；转账收入独立识别 | 正确区分消费、代付、资金转入 |
| apps/web/src/refund-matcher.ts、import-refunds.ts | 支付宝订单前缀关联；微信唯一商户、全额、时间匹配；后导入原单补关联 | 部分及跨期退款先入账，不因原单缺失阻塞 |
| apps/web/src/import-workflow.ts | 取消无依据的亲情卡、原单关联阻塞；升级未入账旧队列；稳定来源去重 | 重复导入不重复记账，保留忽略与稍后处理 |
| packages/accounting/business.ts、domain/accounting.ts | 独立退款、转入、后关联、更正命令 | 余额和消费一致，关联不重复收款 |
| apps/web/src/main.ts、style.css | 旧来源差异表、余额和消费更正预览；移动端集中设置布局 | 用户知道更正影响，历史不静默重写 |

## 明确规则

- 亲情卡 / 亲属卡消费计入消费，不扣本人账户，不创建负债、应收或虚拟资金账户。原始渠道完整保留。
- 单一资金渠道加已知红包、闪购红包等优惠不会当作两个账户。导出金额原样入账，不推算未提供的优惠金额；真实多资金渠道仍保留分摊核对。
- 支付宝优先使用明确原订单号，否则使用退款订单第一个 `*` 或 `_` 前缀，且必须唯一命中已有来源。微信无原订单号时仅唯一商户 / 对方、全额金额、原单早于退款且间隔 90 天内自动关联。
- 独立消费退款在退款发生月冲减消费；独立转账退回只记资金，不创造收入。原单出现后可自动或手动补关联，不追加资金流水。部分消费性质的转账退回，需分配消费冲减时不自动关联。
- 空付款渠道可先记未知账户；明确渠道集中设置。还款和内部转账仍需要两个有效账户。相同尾号有歧义时提供绑定选择。
- 新建余额未知不是零余额。后补余额基准与历史流水沿用现有余额计算规则。
- 已记账来源重新导入不新增交易。出现识别差异时显示当前解释与新解释，预览后明确确认更正；保留原记录 ID、名称、备注及来源凭证，追加更正审计。已有退款关联的交易暂不支持此通用更正入口。
- 队列与渠道映射沿用现有备份、操作日志和加密同步结构，无新增数据库字段；队列本身仍是设备级。

## 验证

运行 `npm test`、`npm run typecheck`、`npm run typecheck:web`、`npm run check:platform`、`npm run build:web`。
安装浏览器 `npx playwright install chromium` 后，运行 `npm run test:web:imports` 验证首次账户设置、改名跨平台复用、亲情卡、红包、还款、退款后关联、重复导入、手机流程及旧版识别更正；`npm run test:web` 覆盖 CSV/XLSX、删除恢复、加密双向同步及备份恢复。

测试使用合成账单和仓库既有 XLSX。用户提到的两份真实账单未提供给当前工作区，因此不将“192 笔降到 7 笔”作为已复现的验收结果。暂不接入大模型 API：本次确定性流程不依赖它。
