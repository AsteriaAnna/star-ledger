# 星账 · 双人版 2.0

这是在原单人离线版上完成的双人版本。资金始终分开归属：放在谁的账户里，与属于谁，是两件事。

## 先在电脑上使用

1. 将整个压缩包“全部解压”到固定文件夹。
2. 打开 `电脑离线版/星账.html`，选择 Edge 或 Chrome 普通窗口。
3. 可以先点左下角“体验示例账本”。示例与真实账本隔离，不写入真实数据，不会同步。
4. 在“设置与同步”中填写两个人的固定昵称，并选择此设备的记录人。
5. 直接导入微信或支付宝账单，软件会按账单原名称建立微信零钱、支付宝余额和银行卡账户；现金等账单中没有的账户可以手动添加。
6. 在“账户与归属”填写当前余额和对应时点。只有原始账单确实缺少核心字段，或退款关系不能唯一确定时，才需要去“转账与核对”。

电脑文件版不需要联网就能记账。本版本还不是 EXE 安装包。手机离线安装需要先发布网站版到 HTTPS 地址，然后添加到主屏幕。

## 三个模式

绿色模式和紫色模式分别展示两个人的账单及资产；“双方存款”集中展示各自的存款，使用绿紫撞色。点击模式时页面和背景旋转过渡，跟随系统减少动态效果的设置。

双方都可以查看、编辑全部数据。设备记录人用于注明修改历史，不是额外的权限隔离；真正的远程访问由 GitHub 仓库权限和加密口令控制。

## 添加账户时填写什么

每个账户包含：名称、账户类型、谁保管、初始余额日期，以及四项资金：

- 绿色方的流动资金
- 绿色方的存款
- 紫色方的流动资金
- 紫色方的存款

四项加起来必须等于你在该时点核对的真实账户余额。

例如一张卡有 8,000 元：你的存款 5,000、你的流动资金 2,000、对方的存款 1,000。你的个人资产包含 7,000 元，对方包含 1,000 元；存款总览显示双方各自的存款，不能再与个人资产重复相加。

初始余额日期表示“该日开始时”的余额。当日及之后的流水更新账户余额；之前的历史账单可以参与消费分析，但不再扣减余额。如果用当天晚上的余额作初始值，请把起始日期设为次日，以免当天流水重复计算。

欠款和应收单独手动填写，不会自动改变银行卡余额。之后记账时选择借入、还款、借出、收回借款，关联对应欠款或应收项目。双方之间的新借款，可通过转账用途记录，不要又手动增加一遍相同借款。

## 普通记账、修改与标签

点击“记一笔”，填写金额、时间、资金所有人和账户，默认使用该所有人的流动资金。

支出余额不足时会要求核对，不会自动挪用对方资金。可先核对初始余额、转出自己的存款，或暂存为待核对。

点击明细中的交易名称可编辑金额、日期、交易对方、分类、标签、账户、资金性质、备注和归属。主要分类只能选一个，标签可选多个。分类和标签在设置中新增、改名、改色或删除，历史名称仍保留。

删除进入回收站。重新导入相同订单不会覆盖你的修改，也不会自动恢复已删除订单。详情可查看原始导入字段及修改历史。已合并的转账金额与两端原记录绑定，需要先解除关联才能修改金额或改成其他类型。

## 转账与存取款

在“转账 / 存取”选择用途：

- 本人账户转账：账户变化，所有权不变，不算消费和收入。
- 存起来：把流动资金划入存款，可以在同一账户内进行，不要求真实转账。
- 交给对方保管：钱移到对方保管的账户，但所有人不变。
- 取回 / 转为流动资金：从自己的存款取出，仍不算收入；实际消费时再记支出。
- 请对方代买：把自己的流动资金放到对方账户，实际买东西时由自己的资金承担消费。
- 赠与对方：所有权变更；个人统计中出资方记支出、接收方记收入。
- 借给对方 / 归还对方借款：同时记录资金变化与双方应收、欠款，不当作生活消费。

微信向他人转账会直接记录为“转账流出”，收到他人转账会记录为“转账流入”：余额立即按原始账单变化，但不混入消费支出和工资等普通收入，也不强制补充用途。交易对方沿用微信账单名称，不需要创建对方的银行卡账户。

本人账户之间的等额流水仍会提出配对建议。两端原始订单都保留，转入明细只作为关联记录，不重复计算。只有在主动选择本人账户转账、对象代管、存取款或借还款时，才展开另一账户和资金归属字段。

确认时可记住内部转账规则。自动规则仅适用于所有权不变、相同转出/转入账户、相同双方交易名称和来源类型、金额相等、十分钟内且只有唯一配对候选的情况。赠与和借还款需要逐次确认。规则可停用。

## 退款

全额退款保留消费记录，净消费金额为零。支付 200 元、退款 50 元，净消费为 150 元。

原订单只有退款状态、没有退款流水时，可以填写已确认退款金额。消费统计会抵扣，但要确认退款入账时间和账户之后，余额才会增加。

有独立退款明细时，退款金额、时间和原始到账渠道会立即记录，退款不算普通收入；是否已经找到原订单，不会阻止明确的退款到账。系统会先用订单号关系自动关联，再结合原订单退款状态、平台、金额、时间、付款渠道和备注处理微信缺少关联号的退款。只有证据不能唯一确定时，才留在核对页。

退款可以关联普通消费、被退回的微信转账，以及“付款后退款而关闭”的订单。原订单状态中的累计退款金额和独立退款流水只抵扣一次，不会重复增加余额。

退款后的净消费归到原订单月份；账户余额在实际退款日期变动。重新导入相同订单时，分类、标签和备注继续保留，机器识别的状态、账户和资金流向会按新规则更新；只有你实际手工修改过的核心字段才会受到保护。

## 导入微信与支付宝

支持 UTF-8、GB18030/GBK CSV 和未加密 XLSX。单文件最大 30 MB，解压后 XLSX 最大 100 MB。不支持 PDF、截图、旧版 XLS 或加密压缩包；先解压再导入里面的明细文件。

先选择原始账单属于谁。付款方式直接沿用微信或支付宝账单中的原始名称，系统结合交易类型和状态还原资金流向，不要求逐条或逐渠道匹配账户。金额、日期、收支方向、付款渠道和订单状态会直接进入账本；银行卡、微信零钱、支付宝余额、花呗和亲情卡都保留原始显示名称。`/` 只表示该列对当前交易不适用，不会创建成账户。双方同名的微信零钱按所属人分别保存；同一人账单中名称完全相同的银行卡可跨平台复用。只有确实缺少核心字段或退款关系无法唯一确定时，才进入处理列表，不使用笼统的“待判断”。银行卡和现金可手动记账；本版没有直接连接银行、微信或支付宝账户，也没有手机后台自动抓取交易功能。

去重优先使用“原账单所属人＋平台＋订单号”，不依赖后来手动修改的金额或分类。无单号记录退回日期、金额、交易对方、商品说明和交易类型组合，完全相同的真实多笔交易需核对后补录。

## GitHub 同步：不需要自建数据库服务器

网站已发布：https://asteriaanna.github.io/star-ledger/ 。首次连接仍需在设备上填写自己的授权和账本加密口令；网站不会自动取得 ChatGPT 插件的授权。

已创建个人私有数据仓库 `AsteriaAnna/star-ledger-data`，分支 `main`。你可以先用它验证自己的电脑与手机同步；双方使用各自 GitHub 账号的方案见下文。

建议区分两个用途：

- 应用代码仓库：保存网站文件，不放账单、备份或令牌。
- 私有数据仓库：保存加密账本 `.starledger/ledger-v2.enc.json`，不用于发布网页。

双人推荐连接方式：

1. 你们各用自己的 GitHub 账号，在一个共同组织中都成为成员；给双方访问私有数据仓库的权限。
2. 新建私有数据仓库，勾选初始化 README，确认已有 `main` 分支。
3. 双方分别在 GitHub Settings → Developer settings → Personal access tokens → Fine-grained tokens 创建自己的令牌。
4. Resource owner 选择对应组织；只选这个私有数据仓库；Repository permissions 中 Contents 设置为 Read and write。若组织要求审批，先由组织管理员批准。
5. 在星账设置里填写相同的仓库所属组织、仓库名称和分支，各自填写自己的令牌。
6. 双方约定相同的账本加密口令，至少 12 个字符，建议使用较长的随机口令并妥善保管。
7. 点击“连接并同步”。第二台设备同步后取得相同的账本。

如果先一个人试用，可以用自己的个人私有仓库。GitHub 当前对“个人仓库的外部协作者”使用细粒度令牌有限制，所以不要假定把对象加为个人仓库协作者就一定能直接连接。推荐采用组织正式成员方式，不共享 GitHub 密码、不把令牌发到聊天或写入代码。

原理与行为：

- 账本在本机用 AES-256-GCM 加密后上传；口令不发送到 GitHub。
- 可选择在本机加密保存令牌，下一次打开需要口令解锁；口令本身不持久保存。
- 本地账单及导出的普通 JSON 备份未做额外静态加密，请保护设备和备份文件。
- 保存后、恢复网络或重新打开可见页面时，已解锁的连接会尝试同步；也可以手动同步。
- 离线记录先留在本机，显示待同步。关闭应用后的后台自动同步不作保证。
- 每次同步合并版本记录，不直接用整本旧账覆盖新账；上传发生冲突时重新读取并重试。
- 同一条记录被双方分别修改时，需要在核对页面选择版本；冲突记录暂不计入余额。
- 只有 GitHub 真正确认上传后才标记已同步；联网失败不会删除本地记录。
- 加密口令遗忘后无法解密远端数据，仍可从持有本地账本的设备导出备份。程序没有口令找回服务。
- 本版单次加密同步文件上限 30 MB，适合两个人的轻量账本，不适合高频大规模数据。

## 手机与 Windows 安装

`网站版`文件夹是完整静态网站，不需要运行数据库服务。发布到支持 HTTPS 的静态网站地址后，iPhone 用 Safari 添加到主屏幕，安卓和 Windows 用支持安装的浏览器安装。

首次需联网加载和准备离线缓存；随后可离线记账。首次安装、应用更新和同步连接都需要在实际设备上验证。

网站已经通过 GitHub Pages 发布。当前提供网页和可添加到桌面/主屏幕的版本，尚未生成 Windows EXE、安卓 APK 或 iPhone 原生安装包。

## 备份、迁移与恢复

设置 → 下载备份，会导出所有版本和回收站记录，不包含 GitHub 访问令牌。

每次大量导入后建议下载一份，并保存到另一处。清除浏览器数据、使用无痕模式、换浏览器或换设备，可能丢失未同步记录。软件更新与文件路径变化前也建议先备份。

设置 → 恢复 / 迁移备份，支持双人版合并恢复，也支持此前单人版 `star-ledger` JSON 备份。旧版缺少账户资料，迁移后标为待核对，不立即影响余额。原单人账本不自动读取或删除。
